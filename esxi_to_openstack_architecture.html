LangGraph 7-Agent Workflow DAG

Durable, resumable graph — SQLite checkpoints pe. SSE events stream karta hai per node. Human Gate pe pause hota hai jab tak admin approve ya cancel kare.

AgentInputAI Kya Karta HaiOutputFailure
1. Discovery vCenter credentials pyVmomi se connect — VM name, CPU, RAM, disk, OS, network, datastore, power state fetch karta hai inventory.json → END (failed)
2. Dependency inventory.json LLM VM names + network ports analyze karta hai — Database, App, Web, Monitoring relationships detect karta hai dep_graph.json → planning skip
3. Risk inventory + dep_graph LLM production tags, CPU usage, critical services score karta hai — high/medium/low risk assign karta hai risk_report.json → default scores
4. Planning inventory + risk + dep_graph LLM optimal migration batch order decide karta hai — dependency order, maintenance windows, parallel groups plan.json → END (failed)
5. Human Gate plan.json interrupt() — graph pause ho jata hai. Admin plan review karta hai, approve ya modify karta hai UI se MigrationRequest cancel → END
6. Migration MigrationRequest + plan Celery tasks spawn karta hai — virt-v2v se VMDK→QCOW2, Glance upload, Nova create, Neutron port attach task_ids[] → END (failed)
7. Validation Migrated VMs list Ping, SSH, CPU/RAM check, service status verify karta hai — health score generate karta hai health_report.json → alert + log
State persisted to data/langgraph_checkpoints.sqlite — resume karo kisi bhi workflow ko POST /api/v1/workflow/{thread_id}/resume se. SSE stream via GET /api/v1/workflow/{thread_id}/stream.

VMware Concepts — Definition + Example (vJailbreak se seekha)

VDDK — VMware Virtual Disk Development Kit
VMware disks ko programmatically access karne ki library. Bina VDDK ke VMDK nahi padh sakte.
Example:
Bina VDDK: Permission denied: /vm/disk.vmdk
VDDK ke saath: vmdk.read(offset=0, size=512MB) ✓
vJailbreak isko /home/ubuntu/vmware-vix-disklib-distrib/ me rakhta hai
CBT — Change Block Tracking
VMware feature jo track karta hai VM disk pe kaunse blocks change hue. Live migration ke liye critical.
Example:
VM total disk: 500 GB
Last 24hr changes: 5 GB
CBT se: Sirf 5 GB copy ✓
Savings: 99% less data transfer!
virt-v2v — Virtual to Virtual Converter
Red Hat ka tool jo VMware VMs ko KVM/OpenStack format me convert karta hai. vJailbreak ka core engine.
Example:
server.vmdk (VMware format)
↓ virt-v2v runs ↓
server.qcow2 (OpenStack/KVM format)
Windows VMs me virtio drivers bhi inject karta hai
govmomi / pyVmomi
VMware vSphere API ke official clients. vJailbreak Go me govmomi use karta hai, hum Python me pyVmomi.
Example:
si = connect.Connect(host="vcenter.example.com")
content = si.RetrieveContent()
vm_list = content.rootFolder.childEntity[0]...
Hot vs Cold Migration
Cold = VM band karke migrate. Hot = VM chal rahi ho tab migrate (CBT se). vJailbreak dono support karta hai.
Hot Migration Steps:
1. VM chal rahi hai → Snapshot lo
2. Base disk copy karo (VDDK+CBT)
3. Delta sync karo (changed blocks)
4. Final cutover — minimal downtime

AI Migration Planning — vJailbreak vs MigrateAI

Real example: 4 VMs ka migration order AI kaise decide karta hai.

❌ vJailbreak (Hardcoded) — Kya Problem Hai
Inventory: VM1-Database, VM2-AppServer, VM3-Frontend, VM4-Monitoring

vJailbreak kya karta hai: "Migrate all" — alphabetical/random order

VM3-Frontend ← migrate (depends on VM2 jo abhi migrate nahi hua!)
VM2-AppServer ← migrate (depends on VM1 jo abhi migrate nahi hua!)
VM4-Monitoring ← migrate
VM1-Database ← migrate last Result: Frontend broken for hours. App down. Data loss risk.
✓ MigrateAI (AI Agentic) — Correct Order
Dependency Agent finds: Frontend → AppServer → Database

Risk Agent scores: Database=HIGH, App=HIGH, Frontend=MEDIUM, Monitor=LOW

Planning Agent decides: Batch 1 (2 AM): VM1-Database [HIGH RISK - migrate first, standalone]
Batch 2 (3 AM): VM2-AppServer [depends on DB - DB already migrated]
Batch 3 (4 AM): VM3-Frontend [depends on App - App already migrated]
Batch 4 (5 AM): VM4-Monitoring [LOW risk - last, monitors others] Result: Zero downtime. Dependencies respected. Production safe.
LLM Prompt (Planning Agent): "Given this VM inventory with dependencies [JSON] and risk scores [JSON], create an optimal migration plan. Database VMs first, then Apps, then Frontends. Respect maintenance windows. Consider CPU/RAM load. Output JSON with batches, rationale, estimated time."
