VDDK — Virtual Disk Development Kit

VMware ka official closed-source library jo VM disks ko directly (block level pe) padhne ki permission deta hai — bina OS ke andar jaaye. Migration ka pehla requirement.

🔑 VDDK Kya Hai — Simple Analogy
Sochlo VM ek sealed box hai. VMDK uski hard drive hai jo box ke andar band hai.
Bina VDDK: Box ke bahar se knock karo — kuch nahi milega. VM OS login karna padega.

VDDK ke saath: VMware tumhe ek special chabi deta hai — seedha hard drive ke blocks padh sakte ho. OS ka koi role nahi.

CBT — Change Block Tracking

VMware ESXi ka built-in feature jo track karta hai — VM disk pe exactly kaunse 512-byte blocks change hue. Hot Migration (live, no downtime) ke liye CBT zaroori hai.

📊 CBT — Simple Analogy
Sochlo VM ki 500 GB hard drive ek 500 page ki kitaab hai.
Without CBT (Cold Migration):
Poori kitaab photocopy karni padegi — 500 pages = 500 GB data transfer. VM band karni padegi.

With CBT (Hot Migration):
CBT batata hai — "sirf page 23, 45, 67 change hue." Sirf woh 3 pages copy karo. 497 pages ka data bachega!
🔢 Real Numbers — CBT Impact
VM DiskCold MigrationHot (CBT) Migration
500 GB500 GB transfer5-15 GB transfer ✅
Downtime4-6 hours (VM OFF)5-10 min cutover ✅
Production riskHigh — long outageMinimal ✅
VM state duringPowered OFFRunning (live) ✅
⏱️ Hot Migration Timeline with CBT
CBT Enable kaise kare on ESXi:
1. VM Settings → Options → General → Configuration Parameters
2. Add: ctkEnabled = TRUE
3. Add: scsi0:0.ctkEnabled = TRUE
4. VM reboot → CBT active

vJailbreak automatically CBT enable karta hai jab tum MigrationPlan mein "Hot Migration" select karte ho.

OpenStack Key Concepts — Migration Context Mein

🖼️ Flavor vs Image
Dono alag cheezein hain — confuse mat karo
Image (Glance): VM ki hard drive — OS, apps sab. QCOW2 format. "Photo of the disk"

Flavor (Nova): Hardware configuration — kitna CPU, RAM, disk size. Like "t2.micro" on AWS.
🌐 Networks in OpenStack
VMware se alag terminology
VMware → OpenStack mapping:
Portgroup → Neutron Network
vSwitch → Open vSwitch (OVS)
VLAN → Neutron Segment
VM NIC → Neutron Port
📊 VM States in Nova
Migration ke time status track karte rehna
BUILD → VM create ho rahi hai
ACTIVE → VM running ✅
ERROR → kuch gadbad
SHUTOFF → powered off
MIGRATING → migration in progress

Kubernetes CRDs — vJailbreak Custom Objects

CRD = Custom Resource Definition. vJailbreak ne K8s mein apne custom objects define kiye hain jo migration state track karte hain. Jaise normal K8s mein Pod, Deployment hote hain — waise vJailbreak mein MigrationPlan, VMwareCreds hain.

CRD NameK8s GroupKya Karta HaiTrigger
VMwareCreds vjailbreak.k8s.pf9.io ESXi/vCenter credentials store karta hai. Create hote hi VM discovery shuru hoti hai Auto-discovery
VMwareMachine vjailbreak.k8s.pf9.io Discovered VM ka K8s representation — CPU, RAM, disk, power state Auto after VMwareCreds
OpenstackCreds vjailbreak.k8s.pf9.io OpenStack target credentials — Keystone URL, admin user/pass Manual create
MigrationPlan vjailbreak.k8s.pf9.io Migration blueprint — source VM, target flavor, network map, schedule Starts migration
MigrationTemplate vjailbreak.k8s.pf9.io Reusable template — common settings save karo, baar baar use karo Manual
RollingMigrationPlan vjailbreak.k8s.pf9.io Entire ESXi host/cluster ki VMs ko waves mein migrate karta hai Batch migration
